Правила проекта — в AGENTS.md (общий файл для Claude Code и Codex). Здесь — только как работает Claude.

## Начало и конец задачи

- В начале: прочитать `docs/STATUS.md` и файл своего модуля `docs/modules/<модуль>.md`. Код читать точечно (grep,
  нужные строки), не исследовать чужие модули.
- В конце: обновить «Сейчас»/«Не проверено» в `docs/STATUS.md` и разделы своего модуля; `npm run check` и `npm run build`;
  если менялся C# — `bash scripts/dotnet.sh build` и перед PR `npm run test:backend`.
- Одна задача — одна сессия. Новую тему начинать в новой сессии (или после `/clear`): память — в файлах, а не в истории.

## Основная и дополнительные сессии

Основная сессия (с владельцем проекта) ведёт ветку, коммиты, PR, общие файлы (AGENTS.md → «Модули») и `docs/STATUS.md`.
Подробно — `docs/session-orchestration.md`. Дополнительные сессии и субагенты:

1. Работают только в зоне своего модуля; правку общего файла или чужого модуля — описать в «Для основной сессии»
   своего `docs/modules/<модуль>.md` (файл, что поменять, зачем).
2. Не делают git, не ставят зависимости, не создают миграции (описывают изменение модели — миграцию делает основная).
3. Не запускают `npm run dev`, `npm run build`, `npm run test:backend` и Docker-стек — это основная сессия, по одному за раз.
   Свои проверки: `npm run typecheck`, `npm test -- <фильтр>`, `npx eslint <свои папки>`, `bash scripts/dotnet.sh build`
   (C# собирает не больше одной сессии одновременно).
4. Ключевые решения из `docs/STATUS.md` не пересматривают — предлагают.
5. В конце — обновляют файл модуля и отвечают 1–3 строками.

Субагентов (Agent) без правок кода — для исследования, ревью перед PR (`backend-design:security-reviewer`,
`schema-reviewer`), функционального тестирования. Модель: Sonnet — интерфейс, маршруты, документация; Opus — схема базы,
права, безопасность, сложный C#; Haiku — механика.

- Локальные разрешения — в `.claude/settings.local.json` (не коммитится).
