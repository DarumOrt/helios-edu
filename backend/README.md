# HeliosEDU: C#-бэкенд

ASP.NET Core (.NET 10), EF Core и PostgreSQL. Курсы доступны после входа:

- `GET /api/courses` — список без разделов;
- `GET /api/courses/{id}` — курс с разделами и материалами;
- `GET /api/health` — доступность процесса;
- `GET /api/health/ready` — доступность базы и таблиц курсов, аккаунтов, сессий и записей, при сбое `503`.
- `POST /api/auth/login` — вход по почте и паролю;
- `POST /api/auth/register` — самостоятельная регистрация студента и сразу вход;
- `GET /api/auth/me` — текущий пользователь;
- `POST /api/auth/logout` — отзыв сессии и удаление cookie;
- `GET /api/users` — список пользователей для администратора и организатора.
- `GET /api/users/classmates?group=...` — одногруппники; студент может запросить только свою группу.

Роль определяется сервером. Студент получает только опубликованные курсы своей группы (`CohortCourse`),
преподаватель — курсы, где он указан как `TutorId`, администратор и организатор — все.
Недоступный курс возвращает `404`, не раскрывая наличие записи. Нет сессии — `401`,
нет права на список пользователей — `403`.

`progress`, `enrolled` и `completed` пока остаются демонстрационными значениями,
общими для посетителей. Персональный прогресс и перенос записи оценок — следующие этапы.

## Запуск API и базы

Нужен Docker Desktop с Linux-контейнерами. Из корня репозитория:

```bash
docker compose --profile backend up -d --build db storage api
```

API доступен на `http://127.0.0.1:8080`. PostgreSQL не публикует порт на хост,
данные сохраняются в именованном томе `postgres_data`. Пароль в Compose —
демонстрационный; изменить его до первого запуска можно через `POSTGRES_PASSWORD`
в `.env`. Для существующего тома смена переменной не меняет пароль в самой базе.

При старте API применяются миграции и однократно добавляются отсутствующие демокурсы
из `HeliosEdu.Api/Data/courses.json`. Существующие записи не перезаписываются.
Схема уже учитывает повторяющиеся ID разделов и материалов внутри разных курсов.

## Вход и демонстрационные аккаунты

При подключённом бэкенде откройте `http://127.0.0.1:3000/login`.

| Роль | Почта |
| --- | --- |
| Студент | `student@student.pspu.ru` |
| Преподаватель | `tutor@pspu.ru` |
| Организатор | `organizer@pspu.ru` |
| Администратор | `admin@pspu.ru` |

Локальный демонстрационный пароль: `HeliosDemo2026!`. Его можно задать через
`DEMO_PASSWORD` в `.env` до первого создания аккаунтов. Это не меняет пароли уже
существующих записей. Все пользователи из демонстрационного набора создаются с этим
паролем. Миграция `ManagementP1` добавляет статусы и таблицы групп. При первом заполнении
создаются 20 групп ИНЭК из расписания 2026/2027 (`Data/cohorts.json`: курс, направление, профиль); `co-1` М1227 изучает все четыре курса,
`co-2` 1237 и `co-3` 1247 — без курсов,
факультет ИНЭК. Повторное заполнение сохраняет изменённые группы и их курсы.

Пароли хешируются `PasswordHasher` из ASP.NET Core Identity. Случайный токен сессии
передаётся в cookie `helios-auth` (`HttpOnly`, `SameSite=Lax`), в PostgreSQL хранится
только SHA-256 токена. Сессия действует 8 часов и сохраняется после перезапуска API;
выход удаляет её из базы, поэтому скопированная старая cookie перестаёт работать.
API не возвращает хеши паролей или токены в JSON. Вход ограничен 60 запросами в минуту
с одного адреса; при работе через Next.js адресом для этого ограничения будет сам Next.js.

Регистрация (`POST /api/auth/register`, тело `{ name, email, password, consent }`) создаёт
только студента без группы и курсов: роль и группа из запроса игнорируются, их назначает
организатор. Пароль — от 8 символов, буквы и цифра; почта уникальна без учёта регистра (`409`).
Ошибки полей приходят как `{ error, fields: { email: "…" } }`. Правила совпадают с
`src/shared/lib/registration.ts`. Отключить регистрацию: `Auth__AllowRegistration=false`.

Cookie по умолчанию требует HTTPS. Только демонстрационный Compose включает
`Auth__AllowInsecureCookies=true` для локального HTTP. Прямые POST-запросы к
`/api/auth/*` должны содержать `X-Helios-Client: web`; CORS не включён. Next.js
дополнительно проверяет `Origin` POST-запросов, передаёт cookie на сервер и сохраняет
`Set-Cookie` в ответе браузеру. Не следует открывать CORS для сторонних сайтов.

При подключённом API переключатель ролей скрыт. Данные сессии интерфейс получает
через SWR; Zustand хранит роли только для прежнего мокового режима. При входе и
выходе полная навигация очищает клиентские кэши предыдущего пользователя.

Интерфейс использует новый дизайн из `main`: знак BrandMark, общие карточки и шрифты,
обложки и виджеты дашборда. Запрос Next.js `/api/users?group=...` передаётся в защищённый
список одногруппников, а `/api/courses?sections=1` сохраняет сборку содержания для
следующего шага и дедлайнов. Расписание ограничено серверной группой студента.
Изменение обложки дополнительно проверяет `course.edit` и доступ к курсу на сервере.

Остальные API пока хранят данные в памяти Next.js. В режиме бэкенда `proxy.ts`
проверяет для них сессию, роль, запрошенный `courseId` и запрет подмены `userId`
студентом. Это ещё не полная предметная авторизация: маршруты, которые принимают
только ID материала или работы, получат проверку принадлежности курсу при переносе
соответствующего модуля. Не стоит использовать эти моки для рабочих оценок.

## Управление (P1)

Контракт и тексты ошибок: [спецификация P1](../docs/backend/p1-management.md).

| Метод и маршрут | Действие | Доступ |
| --- | --- | --- |
| `POST /api/users` | Создать пользователя, вернуть `{ user, temporaryPassword }` | admin, organizer |
| `PATCH /api/users/{id}` | Изменить поля, роль, группу, статус | admin, organizer |
| `GET /api/cohorts`, `GET /api/cohorts/{id}` | Группы с `memberIds` и `courseIds` | admin, organizer, tutor |
| `POST /api/cohorts` | Создать группу | admin, organizer |
| `PATCH /api/cohorts/{id}` | Переименовать, изменить факультет или полный список курсов | admin, organizer |
| `PUT /api/cohorts/{id}/members` | Заменить состав, переводя студентов из прежних групп | admin, organizer |
| `DELETE /api/cohorts/{id}` | Удалить пустую группу (иначе `409`) | admin, organizer |
| `POST /api/courses` | Создать черновик с постоянным случайным `coverColor` | admin, organizer |
| `PATCH /api/courses/{id}` | Изменить карточку и статус, кроме кода | admin, organizer |

Для всех изменений требуется `X-Helios-Client: web`. Пользователь берётся из серверной
сессии. Организатор не назначает `admin` и не меняет администраторов; свою роль нельзя
менять, себя нельзя блокировать. Временный пароль возвращается только при создании,
в базе хранится только хеш. Ошибки полей — `400 { error, fields }`, дубликаты — `409`.
PATCH различает отсутствие поля и `null`: `group: null` / `faculty: null` очищают поле.
Переименование группы одновременно обновляет `Account.Group` студентов.

`status: blocked` удаляет все сессии пользователя. Старые cookie возвращают `401`;
новый вход после правильного пароля — `403` с сообщением
«Учётная запись заблокирована. Обратитесь к организатору.». Неверный пароль остаётся
`401`. Разблокировка разрешает новый вход, но не восстанавливает отозванные сессии.

Как в эталонных моках, `Enrollment` не обходит группу: студент без группы не видит
курсов, черновики и архивы скрыты даже у своей группы. Это уточнение отличается от
варианта «Enrollment или группа» в разделе 2 спецификации. Преподаватель видит свои
курсы во всех статусах, организатор и администратор — все курсы.

## Конструктор курса (P2)

[Спецификация P2](../docs/backend/p2-course-builder.md). Все операции ниже требуют
серверную сессию и `X-Helios-Client: web`. Администратор и организатор изменяют любой
курс, преподаватель — только свой. Студент получает `403`, чужой курс преподавателя
возвращает `404 { error: "not found" }`.

| Метод и маршрут (после `/api/courses/{id}`) | Результат |
| --- | --- |
| `POST /sections` | Новый модуль в конце, `201 Section` |
| `PATCH /sections/{sectionId}` | Название модуля, `200 Section` |
| `DELETE /sections/{sectionId}` | Пустой модуль — `204`, непустой — `409` |
| `PUT /sections/order` | `{ sectionIds }` всех модулей по одному разу, `200 Section[]` |
| `POST /sections/{sectionId}/activities` | Новый материал в конце, `201 Activity` |
| `PUT /sections/{sectionId}/activities/order` | `{ activityIds }` всех материалов модуля, `200 Activity[]` |
| `PATCH /activities/{activityId}` | Поля и перенос через `sectionId`, `200 Activity` |
| `DELETE /activities/{activityId}` | Удаление материала, `204` |

Поля фильтруются по типу, как `ACTIVITY_FIELDS` в Next: видео — ссылка и длительность,
PDF/презентация — страницы и ссылка, тест — срок и длительность, задание — срок,
условие и максимальная оценка. У задания без оценки при создании — `100`.
Тип менять нельзя; лишние поля игнорируются. Пустая строка и `null` очищают
необязательное поле. Ответы не содержат полей со значением `null`.

Миграция `CourseBuilderP2` добавляет `Activity.Description` и `MaxGrade`, старые сроки
в формате даты переводит в полночь UTC. Новые сроки сохраняются как ISO 8601 UTC
с суффиксом `Z`. Исходные идентификаторы не меняются; новые имеют вид `s-xxxxxxxx`
и `a-xxxxxxxx`. Перенос добавляет материал в конец целевого модуля, сохраняя поля;
для EF это удаление и вставка с новым `SectionId`. Порядок остальных материалов
сохраняется. Изменения одного курса сериализуются блокировкой строки курса в транзакции.

Как в моках, некорректный порядок (в том числе повторяющиеся ID) даёт `400 fields`.
Для порядка материалов неизвестного модуля мок тоже возвращает `400 fields.activityIds`;
это поведение сохранено, хотя общий текст спецификации указывает `404` для отсутствующего модуля.
Вопросы тестов, работы студентов и запрет удаления задания со сданными работами,
объявления и трекинг остаются в Next.

## Подключение интерфейса

Для локального Next.js создайте `.env.local` в корне:

```dotenv
BACKEND_API_URL=http://127.0.0.1:8080
```

Перезапустите `npm run dev`. Браузер обращается к прежним `/api/courses*`,
Next.js передаёт запросы в C#. Переменная серверная, CORS не требуется.
Без переменной работают прежние моки. При включённом API сбой соединения или
таймаут возвращает `503`, а не моковые данные; HTTP-ошибки API передаются клиенту.

Сайт тоже в Docker (собранный, без `npm run dev`), с подключённым C# API — по желанию:

```bash
docker compose -f compose.yaml -f compose.backend.yaml --profile backend --profile web up -d --build
```

Остановка без удаления данных:

```bash
docker compose --profile backend stop api storage db
```

## Проверка

При запущенных API и базе, из корня:

```bash
node --test backend/tests/api.test.mjs
node --test backend/tests/auth.test.mjs
node --test backend/tests/management.test.mjs
node --test backend/tests/course-builder.test.mjs
node --test backend/tests/*.test.mjs
```

Для проверки связки с Next.js дополнительно задайте `TEST_WEB_URL=http://127.0.0.1:3000`.
`TEST_API_URL` позволяет изменить адрес API. Тесты проверяют готовность базы,
контракты всех демокурсов, порядок коллекций и `404`. В CI эти проверки выполняются
на настоящем PostgreSQL, затем повторяются после перезапуска API.
Для изменённого демонстрационного пароля задайте `TEST_DEMO_PASSWORD`.

На отдельной демобазе можно также выполнить `node --test backend/tests/lifecycle.test.mjs`.
Эта проверка временно меняет название курса, перезапускает API и подтверждает,
что заполнение моками не затёрло изменение. В конце название восстанавливается.
С `TEST_WEB_URL` она дополнительно проверяет чтение изменённой записи через Next.js
и ответ `503` при остановленном API. Не запускайте её на базе с рабочими данными.
Также проверяется запрет чтения курса после удаления связи с группой, даже если
сохранился старый Enrollment. Общий клиент сериализует файлы тестов локальным сокетом:
проверка перезапуска не прерывает запросы других наборов при запуске через `*.test.mjs`.
Тесты управления создают уникальные данные, восстанавливают состав и курсы `co-1`,
оставляют созданные курсы черновиками и тестовые аккаунты без группы.

## Адаптивное обучение (P5)

Спецификация — [`docs/backend/p5-adaptive.md`](../docs/backend/p5-adaptive.md).
Модуль в `HeliosEdu.Api/Adaptive` работает без ИИ: навыки курса образуют граф пререквизитов,
вопросы привязаны к навыкам, попытки сохраняют снимок вопросов и использованных подсказок.
Приоритет привязок: навык вопроса → навыки материала → все навыки модуля.
Если у модуля нет навыков, чтение навыков или первый ответ создаёт авто-навык.
Добавление ручных навыков сохраняет существующий авто-навык.

BKT после каждого ответа обновляет вероятность освоения: правильный ответ без подсказок
использует положительное байесовское свидетельство, остальные — отрицательное; затем
применяется вероятность обучения. Начальные параметры: PInit=0.3, PLearn=0.15, PSlip=0.1,
PGuess=0.2. Для известных типов угадывание равно 1/N (выбор), 0.5 (да/нет), 0.05 (текст).
Результат округляется до четырёх знаков. Порог освоения — 0.95; автоматического понижения
освоенного навыка нет. Пререквизиты открывают зависимые навыки, преподаватель может
назначить освоение, сбросить результат или разблокировать навык с обязательной причиной.

Следующий материал выбирается по приоритету: закрепление преподавателя → линейный порядок
при отключённой адаптации → тест слабейшего доступного навыка → непросмотренный материал
для повторения → все навыки освоены. Повторный показ той же текущей рекомендации не создаёт
запись или событие. Если для слабейшего навыка нет подходящего задания и материала,
возвращается `review_material` с `activityId: null` и объяснением отсутствия материала.
При отсутствии навыков пустого курса также возвращается `review_material`, без ложного
сообщения об освоении. Это дополнение для неописанного в P5 пограничного случая.
Прогресс — 70% освоенных навыков + 30% завершённых материалов; без тестов учитываются
только материалы. Отсутствие материалов/навыков даёт нулевой вклад соответствующей части.

Доступ ученика P5 проверяется **строго по Enrollments**, статусу опубликованного курса
и серверной сессии. Назначение группе в P1 само по себе не создаёт зачисление P5.
Отдельного API зачислений пока нет; фикстуры тестов создают их в PostgreSQL.
Преподаватель редактирует свой курс, организатор и администратор — любой.
Все изменяющие запросы требуют `X-Helios-Client: web`. Клиент может отправить только
`activity.viewed` и `activity.completed`; `coverage`, если передан, — проценты от 0 до 100,
как в текущем `VideoPlayer` (единица измерения в P5 отдельно не указана).
Остальные события создаёт сервер. Журнал допускает только вставку, что проверяется и EF,
и триггером PostgreSQL. События и действие фиксируются в одной транзакции под блокировкой
курса; она также защищает от одновременных повторных ответов и незавершённых попыток.

Демо-сид адаптирован к актуальному main по согласованию: `c-dor-ai`, четыре навыка ЦОР/ИИ,
12 вопросов в `mq1` (по три на навык), исходные `mq1q1`–`mq1q3` сохранены с ответами.
Сид не перезаписывает настройки, навыки и вопросы уже настроенного курса при перезапуске.
История попыток сохраняется после изменения/удаления материала; при удалении очищаются
его текущие вопросы, привязки и закрепления. Модуль с результатами навыков удалить нельзя.

Проверка только C# (пересылка Next для P5 добавляется отдельно):

```bash
node --test backend/tests/adaptive.test.mjs
```

Тест создаёт отдельный курс и учеников через P1, а сид проверяет только чтением.

## Разработка без Docker для API

Нужен .NET 10 SDK; базу можно оставить в Docker. Настройте
`ConnectionStrings__Database` для доступного PostgreSQL, задайте
`Database__ApplyMigrations=true` и, только для демосреды,
`Database__SeedDemoData=true`. Для локального адреса задайте
`ASPNETCORE_URLS=http://127.0.0.1:8080`.
Для создания демоаккаунтов нужен `Auth__DemoPassword`. Только при локальном HTTP
задайте `Auth__AllowInsecureCookies=true`.

```bash
dotnet run --project backend/HeliosEdu.Api
```

NuGet-зависимости зафиксированы в `packages.lock.json`; Docker использует
`dotnet restore --locked-mode`. При намеренном обновлении пакетов обновляйте
lock-файл через `dotnet restore`, затем проверяйте сборку.

За пределами демонстрационного Compose автоматические миграции и заполнение
по умолчанию отключены. В production миграции должны выполняться отдельным шагом
развёртывания до запуска экземпляров API.
