# HeliosEDU: C#-бэкенд

ASP.NET Core (.NET 10), EF Core и PostgreSQL. Курсы доступны после входа:

- `GET /api/courses` — список без разделов;
- `GET /api/courses/{id}` — курс с разделами и материалами;
- `GET /api/health` — доступность процесса;
- `GET /api/health/ready` — доступность базы и таблиц курсов, аккаунтов, сессий и записей, при сбое `503`.
- `POST /api/auth/login` — вход по почте и паролю;
- `POST /api/auth/register` — самостоятельная регистрация студента и сразу вход;
- `GET /api/auth/me` — текущий пользователь;
- `POST /api/auth/logout` — отзыв сессии и удаление cookie;
- `GET /api/users` — список пользователей для администратора и организатора.
- `GET /api/users/classmates?group=...` — одногруппники; студент может запросить только свою группу.

Роль определяется сервером. Студент получает только курсы с записью в `Enrollments`,
преподаватель — курсы, где он указан как `TutorId`, администратор и организатор — все.
Недоступный курс возвращает `404`, не раскрывая наличие записи. Нет сессии — `401`,
нет права на список пользователей — `403`.

`progress`, `enrolled` и `completed` пока остаются демонстрационными значениями,
общими для посетителей. Персональный прогресс и перенос записи оценок — следующие этапы.

## Запуск API и базы

Нужен Docker Desktop с Linux-контейнерами. Из корня репозитория:

```bash
docker compose --profile backend up -d --build db api
```

API доступен на `http://127.0.0.1:8080`. PostgreSQL не публикует порт на хост,
данные сохраняются в именованном томе `postgres_data`. Пароль в Compose —
демонстрационный; изменить его до первого запуска можно через `POSTGRES_PASSWORD`
в `.env`. Для существующего тома смена переменной не меняет пароль в самой базе.

При старте API применяются миграции и однократно добавляются отсутствующие демокурсы
из `HeliosEdu.Api/Data/courses.json`. Существующие записи не перезаписываются.
Схема уже учитывает повторяющиеся ID разделов и материалов внутри разных курсов.

## Вход и демонстрационные аккаунты

При подключённом бэкенде откройте `http://127.0.0.1:3000/login`.

| Роль | Почта |
| --- | --- |
| Студент | `vagulin@student.pspu.ru` |
| Преподаватель | `kazarinova@pspu.ru` |
| Организатор | `organizer@pspu.ru` |
| Администратор | `admin@pspu.ru` |

Локальный демонстрационный пароль: `HeliosDemo2026!`. Его можно задать через
`DEMO_PASSWORD` в `.env` до первого создания аккаунтов. Это не меняет пароли уже
существующих записей. Все пользователи из демонстрационного набора создаются с этим
паролем; студенты из набора первоначально записываются на все четыре курса.
Заполнение при следующих запусках не восстанавливает удалённые записи на курсы.

Пароли хешируются `PasswordHasher` из ASP.NET Core Identity. Случайный токен сессии
передаётся в cookie `helios-auth` (`HttpOnly`, `SameSite=Lax`), в PostgreSQL хранится
только SHA-256 токена. Сессия действует 8 часов и сохраняется после перезапуска API;
выход удаляет её из базы, поэтому скопированная старая cookie перестаёт работать.
API не возвращает хеши паролей или токены в JSON. Вход ограничен 60 запросами в минуту
с одного адреса; при работе через Next.js адресом для этого ограничения будет сам Next.js.

Регистрация (`POST /api/auth/register`, тело `{ name, email, password, consent }`) создаёт
только студента без группы и курсов: роль и группа из запроса игнорируются, их назначает
организатор. Пароль — от 8 символов, буквы и цифра; почта уникальна без учёта регистра (`409`).
Ошибки полей приходят как `{ error, fields: { email: "…" } }`. Правила совпадают с
`src/shared/lib/registration.ts`. Отключить регистрацию: `Auth__AllowRegistration=false`.

Cookie по умолчанию требует HTTPS. Только демонстрационный Compose включает
`Auth__AllowInsecureCookies=true` для локального HTTP. Прямые POST-запросы к
`/api/auth/*` должны содержать `X-Helios-Client: web`; CORS не включён. Next.js
дополнительно проверяет `Origin` POST-запросов, передаёт cookie на сервер и сохраняет
`Set-Cookie` в ответе браузеру. Не следует открывать CORS для сторонних сайтов.

При подключённом API переключатель ролей скрыт. Данные сессии интерфейс получает
через SWR; Zustand хранит роли только для прежнего мокового режима. При входе и
выходе полная навигация очищает клиентские кэши предыдущего пользователя.

Интерфейс использует новый дизайн из `main`: знак BrandMark, общие карточки и шрифты,
обложки и виджеты дашборда. Запрос Next.js `/api/users?group=...` передаётся в защищённый
список одногруппников, а `/api/courses?sections=1` сохраняет сборку содержания для
следующего шага и дедлайнов. Расписание ограничено серверной группой студента.
Изменение обложки дополнительно проверяет `course.edit` и доступ к курсу на сервере.

Остальные API пока хранят данные в памяти Next.js. В режиме бэкенда `proxy.ts`
проверяет для них сессию, роль, запрошенный `courseId` и запрет подмены `userId`
студентом. Это ещё не полная предметная авторизация: маршруты, которые принимают
только ID материала или работы, получат проверку принадлежности курсу при переносе
соответствующего модуля. Не стоит использовать эти моки для рабочих оценок.

## Подключение интерфейса

Для локального Next.js создайте `.env.local` в корне:

```dotenv
BACKEND_API_URL=http://127.0.0.1:8080
```

Перезапустите `npm run dev`. Браузер обращается к прежним `/api/courses*`,
Next.js передаёт запросы в C#. Переменная серверная, CORS не требуется.
Без переменной работают прежние моки. При включённом API сбой соединения или
таймаут возвращает `503`, а не моковые данные; HTTP-ошибки API передаются клиенту.

Все три сервиса в Docker, с подключённым C# API:

```bash
docker compose -f compose.yaml -f compose.backend.yaml --profile backend up -d --build
```

Остановка без удаления данных:

```bash
docker compose --profile backend stop api db
```

## Проверка

При запущенных API и базе, из корня:

```bash
node --test backend/tests/api.test.mjs
node --test backend/tests/auth.test.mjs
```

Для проверки связки с Next.js дополнительно задайте `TEST_WEB_URL=http://127.0.0.1:3000`.
`TEST_API_URL` позволяет изменить адрес API. Тесты проверяют готовность базы,
контракты всех демокурсов, порядок коллекций и `404`. В CI эти проверки выполняются
на настоящем PostgreSQL, затем повторяются после перезапуска API.
Для изменённого демонстрационного пароля задайте `TEST_DEMO_PASSWORD`.

На отдельной демобазе можно также выполнить `node --test backend/tests/lifecycle.test.mjs`.
Эта проверка временно меняет название курса, перезапускает API и подтверждает,
что заполнение моками не затёрло изменение. В конце название восстанавливается.
С `TEST_WEB_URL` она дополнительно проверяет чтение изменённой записи через Next.js
и ответ `503` при остановленном API. Не запускайте её на базе с рабочими данными.
Также проверяется запрет чтения курса после временного удаления записи студента.

## Разработка без Docker для API

Нужен .NET 10 SDK; базу можно оставить в Docker. Настройте
`ConnectionStrings__Database` для доступного PostgreSQL, задайте
`Database__ApplyMigrations=true` и, только для демосреды,
`Database__SeedDemoData=true`. Для локального адреса задайте
`ASPNETCORE_URLS=http://127.0.0.1:8080`.
Для создания демоаккаунтов нужен `Auth__DemoPassword`. Только при локальном HTTP
задайте `Auth__AllowInsecureCookies=true`.

```bash
dotnet run --project backend/HeliosEdu.Api
```

NuGet-зависимости зафиксированы в `packages.lock.json`; Docker использует
`dotnet restore --locked-mode`. При намеренном обновлении пакетов обновляйте
lock-файл через `dotnet restore`, затем проверяйте сборку.

За пределами демонстрационного Compose автоматические миграции и заполнение
по умолчанию отключены. В production миграции должны выполняться отдельным шагом
развёртывания до запуска экземпляров API.
