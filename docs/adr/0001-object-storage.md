# ADR 0001. Хранилище файлов — SeaweedFS через протокол S3

- Статус: принято
- Дата: 2026-10-28
- Участники: Иван (DarumOrt), Claude; ревью — CodeWizaard

## Контекст

Курсам нужны свои файлы: видео, PDF и презентации в конструкторе, картинки обложек, файлы к сданным
заданиям. Сейчас видео лежит в git (`public/media`), «своя картинка» обложки — data URL в памяти Next
(пропадает при перезапуске), от файла задания сохраняется только имя.

Аудит (27 октября) планировал MinIO. Проверка 28 октября показала: репозиторий `minio/minio` заархивирован
в апреле 2026 года, последний выпуск — 2025-10-15, бесплатные образы и исправления безопасности больше
не выходят (коммерческая линейка — AIStor).

Требования: S3-совместимый API (временные ссылки на загрузку и чтение, CORS), один контейнер для
локального запуска и CI, свободная лицензия, активная поддержка.

## Варианты

| Вариант | Лицензия | Состояние (октябрь 2026) | За | Против |
| --- | --- | --- | --- | --- |
| MinIO CE | AGPL-3.0 | архив, без исправлений | привычный, хорошая документация | уязвимости больше не закрываются |
| **SeaweedFS** | Apache-2.0 | выпуски 4.x каждые 1–3 недели | зрелый, один контейнер `server -s3`, временные ссылки, CORS, веб-интерфейс filer | ключи с ограниченными правами — через JSON-конфиг |
| RustFS | Apache-2.0 | 1.0 — сентябрь 2026 | ближе всех к MinIO по настройке | слишком молодой для данных курсов |
| Garage | AGPL-3.0 | активен | лёгкий | нет веб-интерфейса, строгая лицензия |
| Диск API (volume) | — | — | проще всего | не масштабируется, нет временных ссылок, видео идёт через C# |

## Решение

- Хранилище — **SeaweedFS** (`chrislusf/seaweedfs`, версия закреплена в `compose.yaml`), сервис `storage`.
  Один ключ доступа (`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`) — у него права администратора хранилища,
  но им пользуется только C#; браузер получает лишь временные ссылки.
- C# работает с хранилищем только по **протоколу S3** (`AWSSDK.S3`). Сменить хранилище — значит поменять
  образ и адрес, а не код.
- Файлы загружаются **напрямую в хранилище** по временной ссылке (PUT), которую выдаёт C# после проверки
  прав, типа и размера. Чтение — `/api/files/{id}`: C# проверяет доступ и перенаправляет на временную ссылку
  (видео перематывается — хранилище отдаёт файл частями).
- О каждом файле — запись в таблице `Files` (PostgreSQL): курс, вид, имя, тип, размер, кто загрузил, статус.
- Удаление — по образцу Moodle и Canvas: файл, на который больше ничто не ссылается, 7 дней лежит
  в корзине, потом его удаляет фоновая задача; брошенные загрузки удаляются через сутки; файлы сданных
  работ не удаляются вместе с материалом.

## Последствия

- В `docker compose --profile backend` появляется третий сервис и том `storage_data`.
- Браузер должен видеть хранилище (в разработке — `http://127.0.0.1:8333`); в рабочем развёртывании
  нужен отдельный адрес хранилища за HTTPS и CORS только для адреса сайта.
- Демо-режим файлов не загружает: упор разработки — на серверный режим (см. AGENTS.md).
- Если SeaweedFS перестанет подходить — замена на любое S3-хранилище (RustFS, Ceph RGW, облачное S3)
  без изменения кода; данные переносятся `rclone`.
