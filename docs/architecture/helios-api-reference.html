Адреса и авторизация

Как обращаться Заголовки и условия
Браузер → Next: http://127.0.0.1:3000/api/… Выбрать Сервер; cookie сессии отправляется браузером. Для записи Origin должен совпадать с origin Next.
HTTP-клиент → C#: http://127.0.0.1:8080/api/… Войти через /auth/login, сохранить cookie helios-auth. Изменяющим запросам нужен X-Helios-Client: web.
JSON Content-Type: application/json; camelCase. Null-поля ответов обычно отсутствуют. 204 не разбирается как JSON.
Файл Сначала ticket через API, затем PUT бинарного тела в S3 по uploadUrl. Это исключение из обычного JSON-вызова /api.
Identity Автор и роль берутся из серверной сессии. userId в параметре некоторых административных запросов выбирает объект действия, но не назначает авторство.

Примеры cURL предназначены для C# напрямую. Плейсхолдеры <courseId>, <id> и пароль надо заменить; кнопки только копируют текст, запросы не отправляют. Для Windows используйте curl.exe или Invoke-RestMethod. 

curl -c cookies.txt -X POST 'http://127.0.0.1:8080/api/auth/login' \
  -H 'X-Helios-Client: web' -H 'Content-Type: application/json' \
  --data '{"email":"<ваша почта>","password":"<ваш пароль>"}'

curl -b cookies.txt 'http://127.0.0.1:8080/api/auth/me'
Тот же вход в PowerShell 
$body = @{ email = "<ваша почта>"; password = "<ваш пароль>" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8080/api/auth/login" -ContentType "application/json" -Headers @{"X-Helios-Client"="web"} -Body $body -SessionVariable heliosSession
Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/auth/me" -WebSession $heliosSession

Как читать ошибки

HTTP Смысл
400 Ошибки тела и полей: обычно {error,fields?}. Тексты полей берутся из обработчика; framework binding может вернуть ProblemDetails.
401 Нет действующей серверной сессии или неверные данные входа.
403 Роль, чужой Origin, запрет настройкой; blocked при правильном пароле. Некоторые чужие ресурсы скрываются через 404.
404 Ресурс отсутствует либо не виден текущему пользователю.
409 Конфликт состояния: повторный ответ, лимит попыток, проверенная работа, защищённое удаление и др.
429 Rate limit входа: 60 в минуту с одного адреса; применяется и к операциям auth под этой policy.
501 Ответ Next для отсутствующего серверного endpoint или server-only функции в Демо. Не общий код ошибки C#.
503 Next не связался с API либо файловое хранилище не подключено. Автоматического fallback в Демо нет.
Полный перечень ошибок зависит от операции. Некоторые декларации .Produces пока указывают 200 для фактического 201; поэтому ожидаемый исход берётся из handler и показан отдельно от DTO. Ошибки не сгенерированы автоматически из OpenAPI.

Типовые последовательности

Задача Вызовы
Управление курсом POST /courses → назначить группе через /cohorts → sections/activities → PATCH status=published.
Адаптивный тест GET questions → POST attempts → POST answers / hint → POST submit → GET progress / next. При открытой попытке POST attempts продолжает её.
Файл POST files → прямой PUT uploadUrl → POST complete → сохранить url в материале/обложке либо fileId в работе → GET files/{id}.
Задание POST assignment/{id}/submit → GET submissions → POST review → GET gradebook/me → уведомление.
Корзина курса GET impact → DELETE course → GET courses/trash → POST restore до purgeAt.
