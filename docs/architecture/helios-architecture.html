01Система целиком

Четыре сервиса. Два режима работы.

HeliosEDU — LMS на Next.js и ASP.NET Core. Серверный режим хранит учебные и административные данные в PostgreSQL, а содержимое загружаемых файлов — в SeaweedFS. Демо использует моки Next и память процесса.

В Docker это web (Node.js / Next.js), api (.NET 10), db (PostgreSQL 17) и storage (SeaweedFS). Браузер — клиент этих сервисов. EF Core и AdaptiveEngine работают внутри API; отдельного процесса EF или внешнего сервиса ИИ здесь нет.

02Выбор источника

Источник выбирается для каждого запроса

Интерфейс обращается к /api/* своего Next.js. Route Handler получает источник через getDataSource(), а proxy.ts — через resolveDataSource(). Переключатель записывает cookie helios-data-source через /api/data-source.

Условие Поведение
Нет BACKEND_API_URL Доступен только демо-источник; C# не вызывается.
BACKEND_API_URL задан Можно выбрать серверный источник и войти по паролю. Выбранный режим определяется cookie и resolveDataSource.
DEMO_MODE=off Демо запрещено. Серверный вход и работа требуют доступного C# API.
Выбрано Демо backendRequest / backendForward возвращают null; обработчик использует моки или явный ответ о серверной функции.
Выбран Сервер, C# недоступен 503 с сообщением об ошибке. Автоматической подмены данных моками нет.
Загрузка файлов, корзины, пароли в Демо Серверные операции показывают недоступность; для большинства таких действий применяется serverOnly() → 501.

Хранилища имеют разный срок жизни

PostgreSQL и SeaweedFS сохраняются в named volumes Docker. globalThis в моках переживает HMR, но сбрасывается с новым процессом Next. SWR — кэш ответов в браузере; Zustand/localStorage — клиентское состояние и демо-сессия. Переключение роли в демо не выдаёт серверных прав.

Cookie и localStorage привязаны к браузерному профилю и origin: Chrome и встроенный браузер, а также localhost и 127.0.0.1, могут иметь разные сессии. Для файлов используется ещё один адрес — публичный S3 endpoint, достижимый из браузера.

04От клика до ответа

Проследить запрос через все слои

Next.js выступает BFF: предоставляет браузеру маршруты своего origin и пересылает запросы в API. Метаданные проходят через Next; содержимое файлов передаётся напрямую между браузером и SeaweedFS.

    Функция BFF Ответственность
    backendRequest(path, init) null в Демо. Иначе переносит helios-auth, добавляет X-Helios-Client: web, использует no-store, таймаут 5 секунд, redirect:manual. Переносит Content-Type, Set-Cookie и Location; при сетевом сбое возвращает 503.
    backendJson<T>(path) null либо {ok:true,data} / {ok:false,response}; используется для обработки успешного JSON.
    backendForward(request,path) Проверяет Origin для записи, пересылает метод и JSON. Пустой upstream-404 или 405 превращает в 501 {notImplemented:true}; содержательный 404 ресурса сохраняется.
    serverOnly() 501 {error:'Доступно в режиме «Сервер»',notImplemented:true} для функций без демо-реализации.

    proxy.ts не заменяет авторизацию API

    06Кто делает запрос

    Серверная сессия вместо роли из браузера

    Текущий механизм — случайный непрозрачный токен в HttpOnly cookie и его SHA-256-хеш в таблице LoginSessions. JWT, OAuth-провайдера и refresh-token потока в этой реализации нет.

    POST /auth/loginEmail + пароль
    →
    PasswordHasherПроверка PasswordHash
    →
    32 случайных байта64 hex-символа токена
    →
    LoginSessionsTokenHash + AccountId + ExpiresAt

    Вход по шагам

    1. Email обрезается и переводится в верхний регистр для поиска NormalizedEmail. Пароль проверяется через IPasswordHasher<Account>; обычного SHA-256 пароля здесь нет.
    2. Для отсутствующего аккаунта всё равно выполняется проверка dummy hash, чтобы не делать быстрый отдельный путь «такой почты нет».
    3. Неверная почта/пароль дают 401. Статус blocked проверяется после правильного пароля и даёт 403.
    4. Если hasher запрашивает rehash, хеш обновляется. Удаляются просроченные сессии и предыдущая сессия текущего браузера.
    5. Генерируется криптографически случайный токен, срок — 8 часов. В PostgreSQL сохраняется только Hash(token).
    6. Ответ выставляет helios-auth. Next переносит Set-Cookie из ответа C# в ответ браузеру. JSON содержит UserInfo, без токена и PasswordHash.

    Проверка каждого запроса

    cookie helios-auth
  → проверить: 64 hex-символа
  → SHA256(token)
  → SELECT LoginSessions + Account
     WHERE TokenHash = hash AND ExpiresAt > now
  → отклонить blocked/deleted
  → HttpContext.Items[typeof(Account)] = account
  → Claims: NameIdentifier, Role, Name
  → RequireAuthorization / AccessRules

    Роль и блокировка читаются из базы при запросе. Изменение роли начинает действовать на уже существующей сессии. При блокировке P1 удаляет все сессии аккаунта; сам SessionAuthentication дополнительно отклоняет blocked/deleted-аккаунт.

    Cookie/состояние Назначение Защита и срок
    helios-auth Токен серверной сессии C#. HttpOnly, SameSite=Lax, Path=/, 8 часов. Secure по умолчанию; локально отключается явным флагом.
    helios-data-source Демо или Сервер. HttpOnly, SameSite=Lax, 30 дней. Secure зависит от HTTPS запроса.
    helios-demo-user Выбранный пользователь для реалистичных моковых правил. Доступен JS, может быть подделан. Не является серверной аутентификацией.
    localStorage helios-session Zustand persist для роли/пользователя Демо. Не влияет на роль серверной сессии.

    Регистрация, выход и лимит

    Самостоятельная регистрация создаёт только student без группы; роль и группа не принимаются от клиента. Проверяются имя, email, пароль 8–256 символов с буквой и цифрой, согласие. Сессия открывается сразу. Регистрацию отключает Settings.AllowRegistration=false; Auth-конфигурация задаёт начальное значение при создании Settings. Создание пользователя организатором — другой маршрут P1 и другой сценарий с временным паролем.

    POST /api/auth/logout удаляет запись по хешу текущего токена и удаляет cookie. Login и register используют одну rate-limit policy: 60 запросов в минуту по remote IP, без очереди, при превышении 429. При проксировании через Next несколько пользователей могут иметь общий видимый для API IP — это важно учитывать при дальнейшем production-развёртывании.

    EF Core: мост между объектами и таблицами

    EF Core — ORM, а не отдельная база и не просто парсер. Он строит SQL из запросов C#, материализует строки в объекты, отслеживает изменения и помогает управлять схемой.

    Что означает LearningDbContext

    DbContext — точка работы с моделью и текущим набором отслеживаемых объектов. DbSet<Course> предоставляет вход в запрос к таблице Courses. OnModelCreating и ConfigureAdaptive описывают ключи, связи, длины полей, индексы, JSONB и поведение удаления. Правила модели — не только свойства классов. 

    // Пример чтения: похожий подход используется в Program.cs.
var query = db.Courses
    .AsNoTracking()
    .Where(course => course.Status == "published")
    .Select(course => new { course.Id, course.Title });

// До перечисления строится запрос. Здесь начинается реальное I/O:
var courses = await query.ToListAsync(cancellationToken);

// Схематический SQL; точная форма зависит от provider и проекции:
SELECT c."Id", c."Title"
FROM "Courses" AS c
WHERE c."Status" = 'published';

    IQueryable — ещё не список строк в памяти. Цепочка Where/Select описывает выражение; ToListAsync, SingleAsync, CountAsync и другие terminal operations исполняют его. Не всякий произвольный метод C# можно перевести в SQL: границу базы и памяти нужно понимать явно.

await db.SaveChangesAsync(cancellationToken); // UPDATE в PostgreSQL.

    Без SaveChanges обычное изменение tracked-объекта не становится записью в БД. В то же время ExecuteDeleteAsync, SQL-команды и некоторые другие операции выполняются сразу и минуют стандартный цикл изменения сущностей. Поэтому транзакция охватывает весь сценарий, а не только последний вызов SaveChanges.

    Механизм Как используется здесь
    AsNoTracking Чтение сессий, списков и DTO без намерения менять загруженные сущности. Снижает работу change tracker.
    Include / ThenInclude Загрузка Sections и Activities курса. Навигационные коллекции сами по себе не гарантируют, что данные уже загружены.
    AsSplitQuery Разделяет загрузку графа на несколько SQL-запросов. Это не один гигантский JOIN и не обещание одного round-trip.
    Shadow properties Position для Course/Activity присутствует в модели EF и БД, но не объявлен свойством C#-класса.
    DTO projection UserInfo скрывает PasswordHash; CourseSummary не тянет всё содержание; CatalogCourse ограничивает данные поиска.
    Raw parameterized SQL SELECT ... FOR UPDATE в фильтрах. Интерполируемый SQL через API EF параметризуется; склеивать SQL из пользовательских строк не нужно.

    Миграция ≠ seed ≠ JSON ответа

    Миграция изменяет схему: добавляет таблицу, колонку, индекс или триггер. Seed добавляет начальные строки. Сериализация превращает объект/DTO в JSON. Это разные этапы. Изменение DTO не обязательно меняет схему; добавление свойства EF-сущности обычно требует миграции.

    Файлы *.Designer.cs и LearningDbContextModelSnapshot.cs — снимки модели для EF tooling. Сгенерированный SQL и миграцию нужно проверять: EF не знает намерений продукта и не гарантирует автоматически безопасное преобразование любых существующих данных.

    13Модель ученика

    BKT без магии: вероятность после ответа

    PKnown оценивает вероятность освоения навыка. Это не процент правильных ответов и не оценка за тест. Сервер использует четыре параметра навыка: PInit=0.3, PLearn=0.15, PSlip=0.1, PGuess=0.2; для известных типов вопроса угадывание G определяется самим типом.

    Параметр Смысл
    p / PKnown Вероятность знать навык перед ответом.
    S / PSlip Вероятность ошибки при знании навыка.
    G / guessing Шанс угадать без знания: mcq 1/N, boolean 0.5, short 0.05. PGuess — fallback для неизвестного типа.
    T / PLearn Вероятность научиться после текущего действия. 
    Верно без подсказки:
  p' = p × (1 − S) / [p × (1 − S) + (1 − p) × G]

Ошибка ИЛИ использована подсказка:
  p' = p × S / [p × S + (1 − p) × (1 − G)]

После шага обучения:
  p_new = p' + (1 − p') × T

Сохранение:
  clamp(0, 1) → round(4, AwayFromZero)

    Почему подсказка влияет на знание, но не обязательно на балл

    IsCorrect проверяет сам ответ. Поэтому правильный ответ с подсказкой может принести балл и увеличить счётчик Correct. Но для BKT он считается отрицательным свидетельством самостоятельного знания. Балл и вероятность отвечают на разные вопросы — совпадать им не обязательно.

    Рекомендация с причиной, которую можно проверить

    GET /api/me/courses/{id}/next возвращает одну основную recommendation и список personal. Порядок правил важнее отдельных значений PKnown: закрепление преподавателя имеет приоритет даже перед отключённой адаптацией.

    1. Есть StudentPin → pinned_by_teacher

      Вернуть закреплённый материал. Текст: «Задание назначил преподаватель: {reason}». Закрепление сохраняется до снятия преподавателем.

    2. AdaptiveEnabled=false → linear_order

      Первый незавершённый материал в порядке разделов и активностей. PKnown в выборе не участвует.

    3. Слабейший learning-навык → weakest_skill

      Минимальный PKnown; при равенстве Order, затем Id. Для него выбирается тест с наибольшим числом относящихся вопросов, затем с меньшим числом уже решённых верно, затем по позиции материала.

    4. Нет подходящего теста → review_material

      Если теста нет или все его вопросы уже решались верно, вернуть непросмотренное видео/PDF/презентацию данного навыка. Правильные ответы учитываются по паре ActivityId + QuestionId, чтобы не смешать тесты.

    5. Все существующие навыки mastered → all_mastered

      ActivityId=null. Для пустого курса условие не трактуется как «всё освоено».

    Если подходящего материала для слабого навыка вообще нет, текущая реализация возвращает review_material с activityId:null и объяснением. Это явно отмеченное дополнение к не полностью определённому пограничному случаю спецификации.

    Что означает personal

    Для каждого learning-навыка с PKnown<0.6 перечисляются незавершённые видео/PDF/презентации навыка. Этот список вычисляется на запросе и не создаёт отдельные строки Recommendations.

    Защита от дублей и реакции

    Если последняя рекомендация ученика по курсу остаётся shown и указывает на тот же ActivityId, возвращается она же. Иначе создаётся rec-идентификатор и событие recommendation.shown. Принять рекомендацию не значит автоматически завершить материал.

    Как читать ошибки

    HTTP Смысл
    400 Ошибки тела и полей: обычно {error,fields?}. Тексты полей берутся из обработчика; framework binding может вернуть ProblemDetails.
    401 Нет действующей серверной сессии или неверные данные входа.
    403 Роль, чужой Origin, запрет настройкой; blocked при правильном пароле. Некоторые чужие ресурсы скрываются через 404.
    404 Ресурс отсутствует либо не виден текущему пользователю.
    409 Конфликт состояния: повторный ответ, лимит попыток, проверенная работа, защищённое удаление и др.
    429 Rate limit входа: 60 в минуту с одного адреса; применяется и к операциям auth под этой policy.
    501 Ответ Next для отсутствующего серверного endpoint или server-only функции в Демо. Не общий код ошибки C#.
    503 Next не связался с API либо файловое хранилище не подключено. Автоматического fallback в Демо нет.
    Полный перечень ошибок зависит от операции. Некоторые декларации .Produces пока указывают 200 для фактического 201; поэтому ожидаемый исход берётся из handler и показан отдельно от DTO. Ошибки не сгенерированы автоматически из OpenAPI.

    16История и согласованность

    События обучения, действия плеера и аудит разделены

    Журнал Что хранит Как используется
    LearningEvents attempt.started, ответы, подсказки, рекомендации, просмотр/завершение материала, решения преподавателя. Объяснение P5 и история конкретного ученика курса. Append-only.
    TrackingEvents opened, played, paused, seeked, ratechanged, page_viewed, completed, closed. Аналитика просмотра, сессии и streak. Не заменяет SkillMastery или AttemptAnswers.
    AuditLog Входы, изменения пользователей, групп, курсов, содержимого, настроек, оценок, файлов, корзин и паролей. Административный журнал с русскими названиями и изменениями полей. Append-only.

    Где обеспечивается согласованность

    Действие и его AuditEntry добавляются в тот же DbContext и сохраняются в одной транзакции изменения. В P5 ответы и обновления mastery используют серверные транзакции и блокировки; ограничения ключей не позволяют незаметно сохранить дубликат ответа. Append-only обеспечивается моделью и триггерами базы, а не только отсутствием кнопки редактирования.

    ActivityProgress обновляется PostgreSQL UPSERT: GREATEST для покрытия, времени и страниц, логическое OR для Completed. Одновременные снимки разных вкладок не должны откатить достигнутый максимум. Прочитанность уведомления записывается с ON CONFLICT DO NOTHING, поэтому повторное нажатие безопасно.

    Не одна распределённая транзакция: операция над объектом S3 и запись PostgreSQL — разные действия. Поэтому загрузка имеет состояния pending/ready, а неиспользуемые и брошенные объекты обрабатываются отдельным janitor. Выдача uploadUrl ещё не означает успешную загрузку и привязку.

    17Объектное хранилище

    База хранит сведения. SeaweedFS хранит байты.

    Выбор хранилища зафиксирован в ADR 0001. Files содержит Id, CourseId, Kind, ObjectKey, имя, MIME, размер, владельца, статус и даты. В Course.Cover / Activity.Src сохраняется стабильная ссылка /api/files/{id}, а в Submission — FileId. Временный подписанный URL не хранится как постоянный источник материала.

    Загрузка за четыре шага

    1. POST /api/files с kind, courseId, fileName, size: сервер проверяет права курса, формат и лимит; создаёт pending и выдаёт UploadTicket.
    2. Браузер делает прямой PUT uploadUrl в S3 с выданным Content-Type. upload.ts использует XMLHttpRequest для прогресса отправки.
    3. POST /api/files/{id}/complete: сервер проверяет существование объекта, заявленный размер, переводит его в ready, возвращает StoredFileInfo.
    4. Клиент прикрепляет стабильный url к материалу/обложке либо fileId к своей работе. Проверка прикрепления повторяется на сервере. 
    POST /api/files
{"kind":"document","courseId":"c-dor-ai","fileName":"lecture.pdf","size":20480}

201 → {id, uploadUrl, contentType, expiresAt}
PUT <uploadUrl>  Content-Type: application/pdf  <байты файла>
POST /api/files/<id>/complete  {}
200 → {id,kind,courseId,fileName,contentType,size,url}

    Чтение и воспроизведение

    Браузер запрашивает /api/files/{id} через Next. C# проверяет сессию и доступ, выдаёт 302 на подписанный download URL сроком 1 час. Next сохраняет Location благодаря redirect:manual. Видео/PDF читаются непосредственно из S3; API и Next не прокачивают весь файл через свою память. Upload ticket также действует 1 час.

    Вид Лимит Кто загружает
    video: mp4, webm 1 ГБ Редактор своего курса
    document: pdf 50 МБ Редактор своего курса
    cover: jpg/jpeg, png, webp 5 МБ Редактор своего курса
    submission: PDF/Office/ODT/TXT/ZIP и изображения из FileKinds 50 МБ Студент доступного курса для своей работы

    Адреса и CORS

    Storage__ServiceUrl=http://storage:8333 используется API внутри Docker. Storage__PublicUrl должен быть доступен браузеру, локально — http://127.0.0.1:8333. Нельзя выдавать браузеру контейнерный hostname storage. AllowedOrigins разрешает origin Next для прямого PUT; порт 8888 — интерфейс filer, а не публичный API LMS.

    Жизненный цикл объекта

    pending → ready → trash → физическое удаление. Брошенная pending-загрузка старше суток удаляется. Неиспользуемый ready-файл после суточного grace переносится в trash; через 7 дней удаляется. Вновь используемый trash-файл восстанавливается. FileJanitor учитывает действующие ссылки и снимки корзины, очищает объекты без записи после grace. Очистка запускается фоном; вручную — admin через POST /api/files/cleanup.

    18Постоянные учебные данные

    Работа и оценка — разные записи

    Submission уникальна для courseId + activityId + userId. Студент отправляет текст до 20 000 символов, заранее загруженный файл или оба. Нужен хотя бы один ответ. Пока работа не проверена, пересдача обновляет эту запись; после reviewed сервер отвечает 409.

    Grade хранит значение, автора оценки и время. Проверяют admin и tutor своего курса; organizer читает журнал, но не выставляет оценки. Проверка сохраняет feedback, reviewedBy/reviewedAt, оценку и личное уведомление ученику. 

    POST /api/assignment/<activityId>/submit
{"courseId":"<courseId>","text":"Мой ответ","fileId":"<готовый файл>"}

POST /api/submissions/<submissionId>/review
{"grade":85,"feedback":"Комментарий преподавателя"}

GET /api/gradebook?courseId=<courseId>
GET /api/gradebook/me

    Как получается оценка за тест

    Если выставлена ручная Grade, она имеет приоритет. Иначе журнал использует лучший результат завершённых попыток P5 с пересчётом к maxGrade материала (по умолчанию 100). Снятие ручной оценки возвращает автоматический результат теста. Смена группы не стирает собственные результаты ученика.

    Объявления — общий текст курса

    Объявления хранятся один раз в Announcements; список получателей не размножается. Их видят пользователи с доступом к курсу. Создавать может редактор курса, если AnnouncementsEnabled разрешён настройкой. Заголовок — 3–120 символов, текст — 1–2000.

    Уведомления собираются из трёх источников

    1. Объявления видимых курсов.
    2. Личные записи Notifications, например о проверке работы.
    3. Рассчитанные при чтении сроки заданий/тестов в ближайшие три дня, если ученик ещё не сдавал материал.

    Прочитанность отдельно в NotificationReads с ключом userId + notificationId. У напоминания стабильный id due-курс-материал. Отметить прочитанным можно только своё реально доступное уведомление; повторный запрос не создаёт дубль.

    19От просмотра к показателям

    Снимок прогресса и лента событий — два канала

    Клиентский tracker собирает дискретные события и отправляет пакеты каждые 5 секунд. При скрытии страницы / pagehide использует sendBeacon. Каждый пакет относится к одному курсу. Периодические снимки прогресса идут отдельными запросами, поэтому обновление агрегата не ждёт выгрузки всей очереди событий.

    Канал Содержимое и хранение
    POST /tracking/progress Один снимок: courseId, activityId, activityType, sessionId, coverage, activeTimeSec, completed и метрики плеера. UPSERT в ActivityProgress по userId + courseId + activityId.
    POST /tracking/events courseId + events; до 200 событий в пакете. Сервер назначает пользователя и проверяет ts (сутки назад — минута вперёд, иначе now); сохраняются разрешённые verb, материал, сессия, позиция и payload в TrackingEvents.
    GET /tracking/progress Продолжение просмотра и агрегированная статистика. Для ученика берётся собственный пользователь; клиентский userId не выдаёт чужие данные.

    Coverage, ActiveTimeSec и PagesViewed сливаются максимумом; Completed не снимается. Это агрегат по материалу, а не сумма всех heartbeat всех вкладок. Положение и некоторые счётчики обновляются последним снимком; FirstAt/LastAt и число сессий позволяют анализировать работу во времени.

    Клиентский плеер

    Видео считает покрытие просмотренных временных корзин по 5 секунд; порог завершения — 90%. Снимок отправляется примерно раз в 4 секунды. PDF и презентации учитывают просмотр страниц. Клиентские измерения не следует путать с проверкой знаний: освоение навыка считает BKT по ответам.

    Что читают экраны

    • /analytics/course/{courseId}: по материалам — начавшие/завершившие, количество учеников, среднее покрытие и время.
    • /analytics/lesson/{activityId}?courseId=…: строки учеников и при запросе доступная лента событий урока.
    • /hub/leaderboard?courseId=…: рейтинг по материалам/покрытию/тестам/streak в пределах доступного курса и группы.
    • /schedule?group=…: сетка пар и ScheduleSlots группы с краткими карточками курсов. Студент ограничен своей группой.
    Прогресс карточки курса рассчитывает CourseProgress из навыков и завершённых материалов. Покрытие видео — показатель просмотра конкретного материала. Процент освоения навыка — вероятность BKT. Эти три числа отвечают на разные вопросы.

    Настройки и история изменений находятся в базе

    Settings хранит одну строку на TenantId: AllowRegistration и AnnouncementsEnabled. Публичный GET нужен странице регистрации ещё до входа. PUT и чтение AuditLog разрешены только admin через policy system.manage. 

    GET /api/settings

{"allowRegistration":false,"announcementsEnabled":true}

Отключение регистрации проверяется сервером при POST register; выключение объявлений — при создании объявления.

    Что сохраняет AuditLog

    Время, организацию, автора и его роль, код действия, категорию, тип/id цели, читаемое название на момент действия и JSONB-массив {field,before,after}. Названия уже сохранены, поэтому журнал не превращается в непонятные id после переименования или удаления объектов. Пароли не записываются в changes.

    Неудачный вход тоже даёт запись с введённой почтой, без действующего автора сессии. Журнал append-only: DbContext и триггер базы запрещают изменение/удаление записей. Это отдельная история от LearningEvents ученика.

    Фильтры и страницы

    from/to задают даты включительно по UTC, category/role — точные фильтры, q ищет автора/цель/русское название действия. Новые записи первыми; cursor — последний id предыдущей страницы. По умолчанию 50, допустимо 1–200; nextCursor отсутствует в конце.

    21Восстановление и учётные записи

    Удаление учитывает связи и учебную историю

    Корзина содержимого

    Допустимое удаление модуля или материала создаёт TrashItem со снимком. Материал исчезает из активного графа и расчётов. Снимок материала включает его поля, исходный раздел, позицию, вопросы теста и skillIds. Восстановление возвращает структуру и связанные данные с проверками конфликтов. Непустой модуль и задание со сданными работами защищены от удаления.

    GET /courses/{id}/trash читает корзину курса, POST /courses/{id}/trash/{itemId}/restore восстанавливает элемент. Для каждого элемента выдаётся purgeAt; срок хранения — 7 дней.

    Корзина курсов

    Перед удалением GET /courses/{id}/impact показывает количество учеников, работ, оценок и попыток. DELETE выставляет DeletedAt/DeletedByName: курс исчезает из активных списков, но сохраняет результаты до окончательного удаления. GET /courses/trash и POST /courses/{id}/restore обслуживают восстановление. Через 7 дней purge очищает курс и его зависимые данные.

    Удаление пользователя

    Себя удалить нельзя. Действуют правила управления ролями: organizer не управляет admin. Если учебных данных и назначенных курсов нет, аккаунт можно удалить физически. При наличии истории он обезличивается: имя «Удалённый пользователь», техническая почта вместо прежней, случайный недоступный пароль, Status=deleted, Faculty сброшен. Сессии отзываются, результаты сохраняются по прежнему Id.

    Создание, сброс и смена пароля

    1. Создание управляемого аккаунта или POST /users/{id}/password-reset выдаёт временный пароль и ставит MustChangePassword=true. Сброс отзывает предыдущие сессии.
    2. После входа UI предлагает обязательную смену по этому флагу. Сам флаг не заменяет серверные проверки прав и не является отдельной ролью.
    3. POST /auth/password принимает currentPassword/newPassword, проверяет текущий пароль и правила нового, очищает флаг и отзывает другие сессии.
    4. Хранятся хеши PasswordHasher; тексты паролей не входят в UserInfo и аудит. Одноразово возвращаемый temporaryPassword — часть результата операции управления.

    Границы автоматической проверки

    contract.ts проверяет имена полей и их базовые виды (string/number/boolean/array/object), обязательные UI-поля и лишние API-поля для выбранных DTO. Это не полная проверка вложенных значений, прав или бизнес-ошибок — их проверяют HTTP-тесты.

    Часть JSON-тел читается динамически через ManagementInput, поэтому OpenAPI не описывает все поля запросов и все ошибки. Некоторые .Produces по умолчанию указывают 200 даже там, где обработчик создания фактически возвращает 201. В примерах справочника учитывается код обработчика; схема ответа показана отдельно и не выдаётся за полный перечень HTTP-исходов.

    Особенности CI

    Backend job собирает Next без API URL, запускает серверные контейнеры, сверяет OpenAPI, запускает standalone Next с URL API уже в runtime и выполняет наборы последовательно. Между группами тестов перезапускает API для сброса rate limit входов: 60 запросов в минуту с одного адреса. В конце повторяет базовые API-проверки.

    В новых учебных тестах создаётся отдельный курс, чтобы не портить общий сид c-dor-ai. Definition of done проекта: check и build без ошибок/предупреждений; C# использует TreatWarningsAsErrors. Обновление этого автономного руководства проверяется отдельно и не означает повторный прогон всех продуктовых тестов.

    25От симптома к слою

    Поиск ошибки начинается с источника и адреса

    Симптом Что проверить
    «Сессия недоступна» в другом браузере Тот же origin (localhost/127.0.0.1), профиль, выбранный источник, cookie helios-auth и GET /api/auth/me. Демо-роль в localStorage не создаёт C#-сессию.
    401 Нет/истёк токен, сессия отозвана сбросом пароля или блокировкой. Для локального HTTP проверьте конфигурацию Secure cookie.
    403 Роль, доступ к своему курсу/попытке, Origin и X-Helios-Client для записи; блокировка проверяется после пароля. Настройки могут запрещать регистрацию/объявления.
    404 материала / файла Пара courseId + activityId, видимость курса, DeletedAt, принадлежность файла и статус ready. Недоступный чужой ресурс может скрываться 404.
    409 Дубликат/конфликт, уже сохранённый ответ, завершённая попытка, исчерпанный MaxAttempts, проверенная работа или защищённое удаление.
    501 {notImplemented:true} Явная серверная функция в Демо либо отсутствующий upstream endpoint, обработанный backendForward. Это не 503.
    503 от Next BACKEND_API_URL, процесс API, порт/имя контейнера, readiness. В режиме Сервер моки не подставляются.
    Загрузка получила ticket, но PUT не идёт PublicUrl доступен браузеру, CORS AllowedOrigins совпадает с origin Next, Content-Type взят из ticket, URL не просрочен.
    complete не подтверждает объект Объект реально отправлен, размер/метаданные совпадают, файл принадлежит пользователю. Pending ещё не готовая привязка.
    Видео 302, но не играет Location ведёт на публичный S3 адрес, а не storage:8333; проверить доступность и срок подписанного URL.
    Данные пропали после перезапуска Демо/globalThis сбрасывается. В Сервере проверьте volumes postgres_data/storage_data и выбранную базу.
    Курс виден в оценках, но не открывается Сохранённая собственная история не даёт доступ к материалам после смены группы или перемещения курса в корзину.
    Прогресс разных экранов отличается Различайте BKT-вероятность, покрытие просмотра и составной прогресс CourseProgress. Проверьте отправку событий/снимков и SWR invalidation.
    Нельзя удалить модуль или задание Непустой модуль, результаты навыков или сданные работы защищены. Прочитайте 409 и impact перед удалением курса.
    После restore файл ещё недоступен Проверьте восстановление ссылки и Files.Status; FileJanitor возвращает используемый trash в ready.
    Схема / типы устарели Перегенерировать npm run api:types от свежего API и проверить diff openapi.json/api.gen.ts.

    Для проверки слоя используйте последовательно: Next /api/data-source → C# /api/health/ready → /api/auth/me → нужный ресурс → журналы api/storage. Не удаляйте volumes ради обычной ошибки запуска или валидации.

    26Практика изменений

    Сначала серверные правила, затем единый клиентский контракт

    1. Прочитать AGENTS.md и актуальный код. Уточнить роль, область курса, поля, ошибки и постоянные данные.
    2. Изменить C# модель / EF-конфигурацию и добавить миграцию при изменении схемы. Учесть составные ключи материала и последствия delete/restore.
    3. Реализовать endpoint с RequireAuthorization и серверной проверкой пользователя/курса. Добавить DTO / Produces для OpenAPI.
    4. Сделать тонкий Next Route Handler через backendForward/backendRequest. Для Демо использовать тот же контракт либо явную серверную заглушку.
    5. Вынести клиентский вызов в API фичи, чтение в SWR; обновить права/валидацию shared, если меняется контракт.
    6. Обновить OpenAPI snapshot и api.gen.ts, сверить contract.ts. Добавить unit-тест правила и HTTP-тест границы, когда это нужно.
    7. Прогнать check/build, C# build и подходящие backend-наборы; создать ветку/PR, пройти CI и человеческое ревью.

    Что остаётся архитектурным ограничением

    Демо хранится в памяти одного Next-процесса. Сессии C# — opaque cookie, а не OAuth/JWT. P5 — объяснимый BKT-алгоритм, а не LLM. Снимки и объекты S3 согласуются жизненным циклом, без общей распределённой транзакции. OpenAPI пока не описывает все динамические запросы и ошибки; тесты остаются частью контракта.

    Назначение курса группе, собственная история оценок и текущий доступ — отдельные вопросы. Не возвращайте независимую таблицу зачислений или общую галочку Completed без пересмотра всех правил CourseProgress, P5, трекинга и журналов.

    27Термины на языке проекта

    Короткие определения

    API-first
    UI получает и меняет данные через HTTP-контракт, а не импортирует бизнес-моки напрямую.
    BFF
    Серверный слой под потребности frontend. Здесь эту роль выполняют Route Handlers Next: пересылка и агрегация.
    SSR / Server Component
    Часть подготовки интерфейса выполняется в Node.js. Не означает, что каждый последующий клик требует полной перезагрузки страницы.
    Route Handler
    Файл route.ts с GET/POST/... в App Router, который отвечает на HTTP-запрос.
    Middleware / endpoint filter
    Общий этап вокруг запроса или конкретного endpoint. Здесь проверяет identity, доступ и границы транзакции.
    Authentication
    Установление личности по сессии. «Кто ты?»
    Authorization
    Проверка права конкретного пользователя на действие и ресурс. «Что тебе разрешено здесь?»
    Cookie
    Значение, которое браузер отправляет подходящему хосту. HttpOnly запрещает чтение из JavaScript, но не делает cookie общей для разных браузеров.
    Hash / PasswordHasher
    Хеш токена нужен для поиска сессии без хранения самого токена. PasswordHasher отдельно предназначен для безопасной проверки пароля.
    ORM / EF Core
    Связывает классы и реляционную модель, формирует запросы и сохраняет изменения. Не является PostgreSQL.
    Npgsql
    Провайдер EF и библиотека взаимодействия с PostgreSQL. Знает особенности типов и SQL этой базы.
    DbContext / DbSet
    Контекст модели и отслеживания / вход в запросы определённого типа сущности.
    LINQ / IQueryable
    Язык запросов C# и представление ещё не исполненного запроса, который provider может перевести в SQL.
    DTO
    Объект HTTP-контракта, отобранный для клиента. Не должен автоматически раскрывать все поля EF-сущности.
    PK / FK
    Primary key различает строки. Foreign key связывает таблицы и обеспечивает определённую ссылочную целостность.
    Composite key
    Ключ из нескольких полей. Для Activity важен не один Id, а CourseId + SectionId + Id.
    Owned entity
    Сущность EF, принадлежащая владельцу. Здесь Section принадлежит Course, Activity — Section.
    Shadow property
    Поле модели EF без обычного свойства класса. Здесь Position для порядка.
    Transaction / rollback
    Изменения подтверждаются вместе или отменяются. Нужна для согласованности ответа, BKT и событий.
    FOR UPDATE
    Блокировка выбранной строки до конца транзакции. Здесь — способ сериализовать изменения курса.
    Migration / seed
    Изменение структуры схемы / заполнение начальными строками. Не взаимозаменяемы.
    JSONB
    Тип PostgreSQL для структурированного JSON. В P5 хранит варианты, ответы, подсказки, snapshots и event payload.
    DAG / prerequisite
    Граф без циклов / навык, который должен быть освоен перед зависимым навыком.
    BKT / PKnown
    Bayesian Knowledge Tracing / вероятность освоения навыка по наблюдаемым ответам.
    Snapshot
    Снимок версии вопросов в момент начала попытки. Будущие правки теста его не меняют.
    Append-only
    Исторические записи разрешено добавлять, но нельзя переписывать или удалять обычной операцией.
    Idempotency
    Повтор действия не создаёт дополнительный эффект. Например, повтор submit возвращает прежний результат; повтор answers вместо этого запрещён 409.
    HMR
    Обновление модулей при разработке без полного запуска процесса. globalThis может пережить HMR, но не служит дисковым хранилищем.
    Volume
    Постоянный диск Docker за пределами жизненного цикла контейнера. Здесь volumes содержат PostgreSQL и объекты SeaweedFS.
    Origin
    Схема + хост + порт. Same-origin проверка отличается от правил сопоставления cookie по хосту.
    SeaweedFS / S3
    Объектное хранилище файлов. PostgreSQL хранит метаданные и ссылки; браузер передаёт байты по временным подписанным URL.
    Presigned URL
    Подписанная ссылка с ограниченным временем действия для загрузки или чтения конкретного объекта S3.
    FileJanitor
    Фоновая служба API для брошенных загрузок, неиспользуемых файлов, объектов без записи и очистки истёкших корзин.
    OpenAPI
    Машиночитаемое описание маршрутов и DTO API; из него генерируются TypeScript-типы.
    UPSERT
    Вставка либо обновление при конфликте ключа. В ActivityProgress атомарно объединяет снимки, не уменьшая достигнутый прогресс.
    Soft delete / purge
    Исключение объекта из активных данных с возможностью восстановления / окончательное удаление по истечении срока.
