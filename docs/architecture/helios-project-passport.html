01 / Вся система на одном экране

Как устроен HeliosEDU

Учебная платформа с четырьмя ролями. Интерфейс отправляет запросы через Next.js; сервер C# проверяет доступ и сохраняет учебные данные в PostgreSQL. Большие файлы хранятся отдельно.

Куда идёт запрос

Нажмите на блок, чтобы раскрыть его назначение.
→ → →
Файлы → SeaweedFS / S3
Браузер загружает файл напрямую по временной ссылке, выданной API.
Письма → SMTP-провайдер
Фоновый обработчик API читает очередь из PostgreSQL и отправляет письма.
Сервер — основной режим: данные сохраняются между перезапусками. При сбое API приложение показывает ошибку, а не подменяет данные моками.

      02 / Кто с кем связан

      Один курс — несколько групп

      Курс хранится в одном экземпляре. Группы получают доступ к нему через назначения. У каждого студента остаются собственные работы, оценки и прогресс.

      Пример назначения общего курса

      Реализовано
      Несколько групп у курса
      Выбираются в карточке курса администратором или организатором. Изменение материала видно всем назначенным группам.
      Одна учебная группа у студента
      Перевод меняет доступ к курсам. Прежние результаты сохраняются; старые оценки остаются в «Моих оценках» по правилам удаления курса.

      Аккаунт → сессии

      Accounts · LoginSessions
      Роль, группа, статус, хеш пароля. Токен сессии хранится в БД в виде SHA-256.

      Группы ↔ курсы

      Cohorts · CohortCourses · Courses
      У группы много курсов; курс может быть общим для нескольких групп.

      Курс → материалы

      Разделы и материалы принадлежат курсу. Материал определяется парой courseId + activityId.

      Студент → результаты

      Submissions · Grades · QuizAttempts
      Работы, оценки и попытки тестирования привязаны к студенту и материалу курса.

      Студент → изучение

      ActivityProgress · TrackingEvents
      Прогресс материала, позиция видео, события. Данные используются в аналитике и лидерборде.

      Почта и импорт

      MailSettings · MailCampaign · MailRecipient · AccountActivation · UserImport
      Настройки, очередь, активации и отчёты импорта.

      Что где хранится

      Место Содержимое Что будет после перезапуска

      SeaweedFS Загруженные видео, PDF, обложки и файлы работ Сохраняется в storage_data

      Модули обучения и управления

      Каждый модуль соединяет экран, API и данные. Основные учебные функции уже работают в C# и PostgreSQL.

      →
      featuresФормы, плеер, журнал, аналитика, управление.
      →
      sharedОбщие элементы, типы, права, валидация и запросы.

      C#: Program.cs → endpoint модуля → AccessRules / правила → LearningDbContext → PostgreSQL

      Адаптивность — понятный цикл

      1. 1
        Ответ студента

        Попытка и ответ записываются на сервере.

      2. 2
        Обновление освоения навыков

        BKT оценивает вероятность освоения с учётом ответа, угадывания, ошибки и обучения.

      3. 3
        Рекомендация следующего шага

        Учитываются навыки и зависимости; преподаватель может вмешаться вручную.

      • Видео можно продолжить с сохранённой позиции.
      • Лидерборд строится по данным группы: тесты, завершённые материалы и серия дней.
      • PDF пока представлен упрощённым просмотрщиком со счётчиком страниц; PDF.js и продолжение с места ещё не сделаны.
      04 / Доступ определяется сервером

      Кто что может делать

      Интерфейс скрывает недоступные действия, а C# повторно проверяет роль и доступ к конкретному объекту. Изменение роли в браузере не даёт серверных прав.

      Как работает вход в режиме «Сервер»

      1. Почта + парольФорма → Next.js → C# API.
      →
      2. Проверка аккаунтаХеш пароля, статус пользователя.
      →
      3. Cookie сессииhelios-auth · HttpOnly · срок 8 часов.
      →
      4. Каждый запросСессия → роль → доступ к курсу.
      Пользователь и роль берутся из серверной сессии. В PostgreSQL хранится хеш токена. Выход и блокировка отзывают сессии; демо-вход выбором роли — отдельный сценарий.

      Матрица основных действий

      Действие Студент Преподаватель Организатор Администратор
      «Свой курс» — преподаватель назначен его TutorId. Проверки конкретного курса, пользователя и организации дополняют общую матрицу.

      Доступ студента

      Только опубликованные курсы своей группы. Самозаписи на курс нет. Чужой или недоступный курс возвращает 404.

      Регистрация

      Самостоятельно создаётся только студент без группы. Роль и группу назначает сотрудник с правом управления.

      Ограничения организатора

      Не назначает роль администратора и не управляет администраторами. SMTP, рассылки, импорт и журнал действий доступны администратору.

      05 / Новое в управлении

      От CSV до письма пользователю

      Импорт и рассылки доступны администратору в режиме «Сервер». Получатели и очередь сохраняются в PostgreSQL — отправка не зависит от открытой вкладки.

      Путь массового добавления

      CSV-файлИмя, почта; группа и факультет необязательны.
      →
      ПредпросмотрСопоставление колонок, проверка строк и дубликатов.
      →
      ИмпортАккаунты студентов + отчёт + при выборе приглашения.
      →
      АктивацияПисьмо со ссылкой → пользователь задаёт пароль.
      Правила файла
      UTF-8 · до 1 МБ · до 1000 пользователей · разделитель «,» или «;». Группа должна существовать. Выбранная в форме группа важнее группы из CSV.
      Повтор и ошибки
      Дубликаты по email не создаются. Ошибочные строки попадают в отчёт. Перевод существующего студента требует отдельного флажка. Незакрытая кавычка отклоняет файл целиком. 
      name;email;group;faculty
Иван Примеров;ivan@example.org;М1227;ИНЭК
Анна Примерова;anna@example.org;М1227;ИНЭК
      Адреса example.org — образец структуры, для проверки писем замените их своими тестовыми адресами.

      Что происходит с письмом

      Это схема процесса, она не запускает реальную отправку.

      Что настроить в SMTP

      1. 1
        Реквизиты провайдера

        Host, порт, логин, пароль, email и имя отправителя.

      2. 2
        Шифрование

        STARTTLS обычно 587; SSL/TLS обычно 465. Используйте значения своего провайдера.

      3. 3
        Проверка

        Сохранить → проверить подключение → отправить письмо на собственный адрес.

      4. 4
        События

        Включить нужные уведомления: создание аккаунта, приглашение, группа, назначение или публикация курса.

      Важные свойства очереди

      • Письмо и бизнес-изменение сохраняются одной транзакцией.
      • Фоновый MailWorker отправляет не чаще одного письма в секунду на БД.
      • Временные ошибки: до трёх попыток с паузами 30 и 60 секунд.
      • Повтор операции с тем же UUID и содержимым возвращает прежний результат.
      • После аварии с неизвестным исходом отправка автоматически не повторяется: нужна проверка почтового журнала.
      • «Принято SMTP» не подтверждает попадание в ящик; проверьте входящие и спам.
      Настоящий SMTP-провайдер ещё не настроен. Локальный SMTP проверен тестами. До настройки нельзя утверждать, что письма доставляются на внешнюю почту.
      Ссылка активации действует 48 часов. Без отправки приглашений новые CSV-аккаунты создаются без известного пароля: для входа нужно отправить приглашение позднее. MAIL_PUBLIC_URL должен указывать на адрес платформы, доступный получателю.

      Как связаны контейнеры

      Браузер → localhost:3000
Next.js → http://api:8080
C# API → db:5432

Браузер → 127.0.0.1:8333 (временная ссылка)
      compose.backend.yaml задаёт BACKEND_API_URL для контейнера web.

      Для показа с другого компьютера

      localhost относится к компьютеру посетителя. Нужен доступный сетевой адрес хоста и разрешённый порт 3000.

      • Для файлов задайте STORAGE_PUBLIC_URL и STORAGE_ALLOWED_ORIGINS с доступным адресом.
      • Для приглашений задайте MAIL_PUBLIC_URL с тем же доступным адресом сайта.
      • Текущие порты API и хранилища привязаны к 127.0.0.1; внешнюю публикацию нужно настроить отдельно.
      Резервная копия: postgres_data + storage_data + mail_keys. Команда удаления томов уничтожит сохранённые данные. Для обычной остановки достаточно остановить контейнеры.

      Если не получается войти

      • Проверьте, что выбран именно «Сервер».
      • Убедитесь, что четыре контейнера работают.
      • Проверьте /api/health/ready — ожидается status: ok.
      • Не перепутайте студенческий домен: student@student.pspu.ru.
      • Если пароль меняли, используйте актуальный или сброс через администратора.
      Для просмотра интерфейса без сервера можно выбрать «Демо». В этом режиме вход выполняется выбором роли; CSV, SMTP и реальные загрузки файлов недоступны.
      08 / Приёмка через интерфейс

      Как проверить, что всё работает

      Проводите проверки в режиме «Сервер» на тестовых данных. Флажки ниже — ваш личный список проверки в открытой вкладке; это не результаты автоматического тестирования.

      Автоматические проверки проекта

      npm run check
npm run build
npm run test:backend

      check объединяет TypeScript, ESLint, форматирование и модульные тесты. Серверные тесты используют отдельный стек; запускайте один набор на машину.

      В журнале доработки зафиксированы 55 модульных и 150 серверных тестов, успешный check и сборка в Linux Docker. При подготовке этого документа полный набор заново не запускался; текущая сборка Docker и доступность сайта/API проверены в этой сессии.
