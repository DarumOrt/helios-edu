# HeliosEDU в Codex: кнопки и повседневная работа

Настройки действий лежат в `.codex/environments/environment.toml`, окружение называется **HeliosEDU**.
Кнопки действий находятся в верхней панели чата; в узком окне часть может быть в меню действий.
Они запускают обычные команды в терминале текущей рабочей копии. Это локальный сайт, не выкладка
на `heliosedu.ru`.

Если действия пока не появились, откройте настройки Codex → локальные окружения
(Local environments) и выберите окружение HeliosEDU для этой папки. Проверьте, что чат открыт
в рабочей копии с этим файлом. До слияния ветки настройки не появятся в старом main автоматически.

## Что делают кнопки

| Кнопка | Команда | Когда нажимать |
| --- | --- | --- |
| **Сайт** | `npm run dev -- --port 3000` | Открыть интерфейс для работы; дождаться Ready, затем открыть http://localhost:3000 |
| **Сервер** | `docker compose -p heliosedu --profile backend up -d --build db storage api` | Запустить или обновить локальный C# API, базу и хранилище; Docker Desktop должен работать |
| **Проверить** | `npm run check` | Проверить типы, линтер, формат и тесты; успешный результат — завершение без ошибок |
| **Сборка** | `npm run build` | Проверить production-сборку; сначала остановить сайт |
| **Тесты API** | `npm run verify:backend` | Собрать Next и проверить его вместе с C# и отдельной тестовой базой; сначала остановить сайт |
| **Остановить сервер** | `docker compose -p heliosedu --profile backend stop api storage db` | Остановить локальный сервер, сохранив данные |

**Как остановить сайт:** перейти в терминал, где работает «Сайт», и нажать `Ctrl+C`.
Кнопка «Остановить сервер» останавливает Docker, а не терминал Next.
Если порт 3000 занят, не запускайте вторую копию: проверьте уже открытый терминал.

## Первый запуск

1. Нужны Node 24, npm 11 и Git for Windows с Git Bash; для серверного режима — работающий Docker Desktop.
2. В новой локальной папке один раз выполнить `npm ci`. Для новых рабочих копий Codex это делает setup
   выбранного окружения. `node_modules` между рабочими копиями не копируется.
3. Для серверного режима в локальном `.env.local` должно быть `BACKEND_API_URL=http://127.0.0.1:8080`.
   Файл не публикуется; Codex копирует его из исходной папки по `.worktreeinclude`.
   Без этой переменной доступно демо.
4. Нажать **Сервер**, затем **Сайт**. На входе выбрать нужный режим данных.
   В демо достаточно выбрать роль; в серверном режиме нужен локальный аккаунт.

Для быстрого просмотра демо достаточно кнопки «Сайт»; Docker не требуется.

## Обычный рабочий день

- Вы формулируете задачу в чате. Агент сам читает состояние проекта и нужный модуль.
- Вы можете запускать сайт, смотреть изменения и нажимать «Проверить».
- Агент выполняет свои обязательные проверки и показывает diff и краткий результат.
- Перед принятием изменения вы просматриваете diff; публикацию ветки и PR можно поручить агенту
  отдельной просьбой. Слияние PR остаётся за вами.

## Чтобы процессы не мешали друг другу

- Перед «Сборкой» и «Тестами API» остановить «Сайт» через `Ctrl+C`: у них общая папка `.next`.
- «Тесты API» запускать только один раз на всю машину. Прогон занимает примерно 6–8 минут,
  временно останавливает локальный `heliosedu`, использует отдельный `heliostest` и затем запускает
  прежний сервер. В это время не нажимать «Сервер» и не запускать другую сборку C#.
- При аварийном прерывании серверных тестов показать агенту терминал: скрипт мог не дойти до
  восстановления локального стека. Не выполнять `docker compose down -v`: эта команда удаляет данные.
- Несколько рабочих копий не означают несколько независимых баз: локальный сервер общий.
- Ошибки и вывод сохраняются в терминале; подробные серверные тесты — в `.test-backend/`.

## Команды для терминала

Все команды кнопок можно выполнять вручную. Для C# дополнительно доступны:

```text
npm run build:backend
node scripts/run-bash.mjs scripts/dotnet.sh migration ИмяМиграции
npm run api:types
```

Обёртка `run-bash.mjs` выбирает Bash установленного Git на Windows, а не запускатель WSL;
на Linux и macOS использует обычный Bash. Глобальные PATH и настройки терминала не меняются.
