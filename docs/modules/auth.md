## Готово
- В режиме «Сервер» администратор переключает роль в рамках своей сессии. Маршрут /api/auth/preview создаёт личную копию курса с тестовыми аккаунтами. Возврат, выход или удаление сессии очищают её схему PostgreSQL. Запрос из вкладки со старой ролью получает 409 при записи.
- Серверная сессия на каждом запросе читает организацию и текущие факультеты организатора. Изменение полномочий применяется также к уже открытой сессии.
- Вход по паролю. Приём заявок закрыт по умолчанию, открытые заявки создаются без сессии и роли.
  После назначения роли получатель устанавливает пароль по приглашению. Блокировка закрывает сессии.
- Лимит входов 60/мин на адрес; неудачные входы — в журнал. На рабочем сервере адрес — пользователя
  (`Auth/ClientAddress.cs`, включается `Auth__TrustClientAddressHeader`), локально и в тестах — общий (сервер Next)
- Первый администратор на чистой базе: `Auth/FirstAdmin.cs` (`Admin__Email`, `Admin__Password`)
- Смена пароля, временный пароль → `mustChangePassword`, плашка в кабинете

- Вход и регистрация используют [«волны из формул»](../design/formula-waves.md) по теме сайта.
  На входе Chrome показал около 60 кадров/с на 1440 и 3840 px. Движение приостанавливается
  вне экрана, в скрытой вкладке и при уменьшении движения.
- Подпись под HeliosEDU, логотип, приветствие и нижняя подпись на входе и регистрации приходят из `/api/branding`. При пустых настройках используется оформление ПГГПУ.

## Ловушки
- Лимит входов общий для тестов: длинные наборы делать после `restart api` (так в CI)

## Что осталось
- Самостоятельный запрос сброса пароля по почте: пока ссылку активации/установки отправляет администратор

Одноразовые ссылки: `/activate#token=…`, хеш в БД, 48 часов, отзыв при смене email/пароля/статуса.
Параллельное использование сериализовано блокировкой аккаунта; все старые сессии отзываются.
