# Модуль «deploy» — выкладка на сервер и установка у организаций

Устав и отчёт модуля (≤40 строк). Общие файлы (см. AGENTS.md → «Модули») меняет основная сессия.

## Зона
- `compose.prod.yaml`, `Caddyfile`, `scripts/` (копии, установка), `.github/workflows/` (сборка образов, выкладка),
  `docs/deploy.md` (инструкция); в C# — только то, что нужно для запуска на сервере (первый администратор, адрес клиента)

## Решено с владельцем проекта (14.11)
- Timeweb: обычный облачный сервер (Ubuntu 24.04, Москва, 2 ядра / 4 ГБ / от 50 ГБ). «Базы данных» и App Platform
  не берём — проект должен переноситься на сервер образовательной организации (нужны только Linux, Docker, домен, почта).
- Один домен, планируется `heliosedu.ru`: сайт — `heliosedu.ru`, файлы — `files.heliosedu.ru` (отдельный адрес:
  браузер берёт файлы прямо из хранилища, а файлы студентов не должны считаться частью сайта).
- Перед сайтом — Caddy (сам получает HTTPS); в инструкции дать и вариант «за собственным Nginx организации».
- Образы собирает GitHub Actions (GHCR), сервер их только скачивает. На сервере руками ничего не правим.
- Локальный Docker остаётся для разработки и тестов; база сервера с ним не связана.

## Предложено, владелец ещё не подтвердил
- Выкладка — кнопкой «Run workflow» с номером версии, а не на каждое слияние; перед ней — копия базы.
- На сервере чистая база без демо-данных ПГГПУ; тестовые аккаунты — через импорт CSV.

## Этап 0 — подготовка кода (до покупки сервера)
1. Первый администратор без демо-данных (сейчас учётные записи создаёт только `Database__SeedDemoData`).
2. Лимит входов по адресу пользователя: сейчас все запросы идут с адреса Next — общий лимит 60 в минуту на весь сайт.
   Передать адрес клиента Caddy → Next → C# так, чтобы его нельзя было подделать снаружи.
3. `compose.prod.yaml`: защищённые cookie (без `Auth__AllowInsecureCookies`), `DEMO_MODE=off`, без демо-данных,
   `Storage__PublicUrl`/`AllowedOrigins`, `MAIL_PUBLIC_URL`, наружу только 80/443; пароли — из `.env` на сервере.
4. Проверить, как отдаются файлы работ студентов (показ в браузере или скачивание) — не проверено.
5. Копии: база (`pg_dump`), том хранилища, том `mail_keys`; хранить вне сервера; описать восстановление.
6. Сборка образов с номером версии, выкладка, откат; `docs/deploy.md` для владельца и для организации.

## Дальше (после этапа 0)
Покупка сервера и домена → настройка сервера (SSH-ключи владельца и второго разработчика, сетевой экран, Docker) →
первый запуск → почта на домене (SPF/DKIM; узнать у поддержки, открыты ли исходящие почтовые порты) →
копии и проверка «сайт жив» → пробное тестирование.

## Для переноса в организацию осталось

- Лицензия репозитория (решение команды); оператор персональных данных — организация
