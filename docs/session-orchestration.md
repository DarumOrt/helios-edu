# Как работаем в Codex и Claude Code

Основной режим — один ведущий чат на задачу. Почти каждая задача затрагивает C#, контракт,
права или другие общие файлы, а локальный сервер на машине один. Память в файлах помогает
продолжать работу в новом чате без пересказа проекта.

## Где контекст

| Файл | Что хранит |
| --- | --- |
| `AGENTS.md` | общий порядок работы, границы модулей, команды, критерии готовности |
| `docs/STATUS.md` | состояние main, текущая работа, открытые PR, принятые решения и непроверенное |
| `docs/modules/<модуль>.md` | зона, контракт, проверки, готово, ловушки, что осталось |
| `docs/backend/`, `docs/adr/` | подробные контракты и причины архитектурных решений |
| `ROADMAP.md` | план продукта; незавершённые ветки не отмечаем как выпущенные |
| `docs/codex.md` | кнопки и повседневные действия владельца в Codex |

Личные заметки агентов дополняют эти документы, но актуальное состояние кода проверяем по Git.
Секреты и личные сведения в публичную документацию не переносим.

## Роли

- Владелец ставит задачу, при желании сам запускает сайт и проверки кнопками, смотрит результат,
  принимает продуктовые решения и вливает PR.
- Ведущий агент читает контекст, реализует задачу, ведёт Git и общие файлы, проверяет результат,
  обновляет документы и сообщает ограничения. Просьба владельца делать базовые действия самому
  не освобождает агента от проверок его изменений.
- Ревью C# и изменений прав — с учётом участия второго разработчика CodeWizaard.
- Дополнительные агенты подключаются по явному запросу владельца. Обычной задаче они не требуются.

## Цикл задачи

1. Прочитать `STATUS.md`, нужный модуль, статус Git и diff. Сверить незавершённую работу и ветку.
2. Обновить сведения через `git fetch origin`. Новую задачу начать от актуального `origin/main`
   в ветке `codex/<тема>` (для Claude — `claude/<тема>`). Чужие правки сохранить.
   В грязной папке автоматически не делать stash/rebase; взять отдельную рабочую копию.
3. Сделать точечное изменение и проверки по ходу: типы, нужные тесты, линтер, сборка C# при необходимости.
4. Перед PR: `npm run check`, `npm run build`; при изменении C# — серверные тесты.
   Для изменения Next.js также проверить связку с API, а не только демо.
5. Обновить `STATUS.md` и файл модуля в том же PR, по коммиту на задачу. Слияние — после просмотра владельцем.
6. Ответить коротко: результат, проверки, что не проверено, действия после слияния.
   Новая тема начинается в новом чате; состояние остаётся в документации.

## Общие ресурсы

- Общие файлы перечислены в `AGENTS.md`; одновременно их меняет один ведущий агент.
- `npm run dev` и `npm run build` не запускаются одновременно в одной рабочей копии.
- Серверные тесты и сборка C# выполняются по одному на машину. Рабочие копии используют общий
  стек `heliosedu` на 8080/8333; тесты временно заменяют его отдельным `heliostest`.
- Рабочие копии из Claude остаются обычными git worktree: их не нужно переименовывать или удалять
  ради перехода в Codex. Незавершённые файлы сохраняются на месте.
- Codex копирует `.env.local` в свои локальные рабочие копии по `.worktreeinclude`;
  установка зависимостей описана в `.codex/environments/environment.toml`.

## Если владелец запросил параллельную работу

Задачи должны иметь независимые файлы; C# меняет не больше одного исполнителя. Ведущий агент
оставляет себе зависимости, миграции, Git, общий контракт, сборку Next и запуск Docker.
Исполнитель читает `AGENTS.md`, `STATUS.md` и свой модуль, меняет только оговорённую зону,
запускает точечные проверки и обновляет отчёт модуля. Нужные правки чужих или общих файлов
описывает в разделе «Для основной сессии». Исследование и ревью могут быть без изменений кода.

## Проверка интерфейса

Использовать доступный браузер Codex: проверять реальный сценарий, читаемость, обе темы при их изменении
и узкий экран. Успешный HTTP-запрос не заменяет визуальную проверку. Если браузер или сервис недоступен,
указать, что именно не удалось проверить. Не требовать инструментов и названий моделей из Claude Code.
