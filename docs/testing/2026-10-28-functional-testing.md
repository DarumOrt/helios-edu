# Функциональное тестирование HeliosEDU — 2026-10-28

Ручная проверка функционала под четырьмя ролями (студент, преподаватель, организатор, администратор)
в обоих режимах данных: **«Демо»** (моки Next) и **«Сервер»** (C# API + PostgreSQL в Docker).

- Состояние кода: `main` на `91d50cd` (после #28). Код при проверке не менялся.
- Способ: API через `curl` к Next (`localhost:3000`) и встроенный браузер для интерфейса.
  Тестировщики — агенты Haiku, по одному на роль, по очереди; ключевые находки перепроверены по коду.
- После проверки демо-база PostgreSQL пересоздана из исходного сида, тестовых данных не осталось.

Обозначения режима: **С** — сервер, **Д** — демо, **С+Д** — оба.

## 1. Серьёзные ошибки

### 1.1. Смена обложки курса: «Курс не найден» (С)

- **Шаги:** организатор создаёт курс (черновик или опубликованный) → страница курса → «Сменить обложку» → любой цвет.
- **Получено:** `PUT /api/courses/{id}/cover` → `404 {"error":"Курс не найден"}`. Ошибка видна только во всплывающем
  уведомлении, выбранный цвет остаётся на экране до перезагрузки, после F5 возвращается прежний.
- **У исходных курсов** (`c-dor-ai` и др.) запрос отвечает 200, но цвет хранится в памяти Next
  (`src/mocks/course-cover-store.ts`) и пропадает при перезапуске; в PostgreSQL ничего не пишется.
- **В демо** работает.
- **Причина:** [`src/app/api/courses/[id]/cover/route.ts`](../../src/app/api/courses/[id]/cover/route.ts)
  ищет курс только через `findDemoCourse` и не вызывает `backendForward`. Эндпоинта обложки в C# нет.

### 1.2. В новом серверном курсе студент не может пройти тест (С)

- **Шаги:** организатор создаёт курс → привязывает к группе М1227 → публикует; преподаватель добавляет тест с вопросами;
  студент группы открывает курс (виден, 200) и начинает тест.
- **Получено:** `POST /api/courses/{id}/quizzes/{quizId}/attempts` и `GET .../questions` → `404 "Курс не найден"`;
  `GET /api/me/courses/{id}/progress` → `403 "Вы не записаны на этот курс"`.
- **Причина:** `AdaptiveScopeFilter.cs` и `AccessRules.IsAdaptiveStudent` требуют строку в таблице `Enrollments`,
  а она создаётся только при начальном заполнении (`backend/HeliosEdu.Api/Data/DemoData.cs:74`). Публикация и
  привязка к группе запись не создают, эндпоинта записи нет. Итог: тесты и адаптивное обучение работают только
  в четырёх исходных курсах.
- **В демо** тест в новом курсе стартует и принимает ответы.

### 1.3. Преподаватель не может править карточку своего курса (С+Д)

- `PATCH /api/courses/{id}` (название, описание, категория, статус) → 403 для преподавателя, даже на своём курсе.
- По матрице у преподавателя есть `course.edit`, но маршрут проверяет `course.create`
  ([`src/app/api/courses/[id]/route.ts:32`](../../src/app/api/courses/[id]/route.ts)), в C# — `course.manage`.
- В интерфейсе кнопки редактирования карточки у преподавателя нет: только «Сменить обложку» и «Редактировать содержание».
- Следствие: преподаватель не может опубликовать свой черновик.

### 1.4. Оценка за новый курс теряется (Д)

- Преподаватель оценивает работу в курсе, созданном в демо: `POST /api/submissions/{id}/review` → 200, студенту
  приходит уведомление «Оценка выставлена».
- Но `GET /api/gradebook/me` не содержит этого курса, а `GET /api/gradebook?courseId=…` возвращает `[]`.
- **Причина:** `src/mocks/gradebook-store.ts` знает только курсы из начальных данных.
- На сервере тот же сценарий работает.

## 2. Отсутствующий функционал

### Студент

| Чего нет | Подробности |
|---|---|
| Запись на курс | Ни API, ни кнопки. `POST /api/me/courses/{id}/enroll` → 501. Самостоятельно зарегистрированный студент без группы видит 0 курсов |
| Статус сданной работы | После сдачи страница задания показывает пустую форму, без статуса и текста. Повторная сдача молча перезаписывает работу |
| Загрузка файла к заданию | `SubmissionForm.tsx` отправляет только имя файла, содержимое не передаётся |
| Форум и обсуждения | Тип активности `forum` есть в данных («Обсуждение: этика ИИ»), страницы и API нет |
| Сертификаты, смена пароля, календарь сроков сдачи | Не найдены (сроки — только блок «Сдать» на дашборде) |

### Преподаватель

| Чего нет | Подробности |
|---|---|
| Создание курса | По правилам `course.create` — только admin и organizer; кнопки нет. **Нужно решение команды**, должен ли преподаватель создавать курсы |
| Продление срока для отдельного студента | Срок (`due`) меняется только у материала целиком |
| Рубрики, посещаемость, рассылка по группе | Не найдены |
| Развёрнутые комментарии к работе | Только одно поле «Комментарий» при оценке |

Экспорт журнала есть: кнопка «Экспорт CSV» на `/gradebook`.

### Организатор и администратор

| Чего нет | Подробности |
|---|---|
| Удаление курса | `DELETE /api/courses/{id}` → 405 в обоих режимах. Есть только статус «в архиве» |
| Удаление пользователя | `DELETE /api/users/{id}` → 405. Есть только блокировка |
| Сброс пароля | Нет маршрута и кнопки. Временный пароль выдаётся один раз при создании |
| Настройки системы и журнал действий в C# | `/api/settings` и `/api/audit` живут в памяти Next, пропадают при перезапуске. Запрет регистрации проверяет только Next, сам C# его не знает |
| Фильтры журнала | Только текстовый поиск, нет фильтров по дате, действию и роли. В записи «Изменён пользователь» не видно, что изменилось |
| Полнота журнала | Не пишутся модули, материалы, вопросы тестов, объявления, входы и выходы |

### Тесты (quiz)

- **Нет лимита попыток.** Каждое открытие страницы теста создаёт новую попытку, а в оценку идёт лучшая
  (`GradesEndpoints.cs`), то есть пересдавать можно бесконечно.
- Тест можно отправить почти без ответов (11 из 12 пустых) — без предупреждения на уровне API.

## 3. Режим «Сервер» хранит часть данных не в PostgreSQL

В серверном режиме эти разделы обслуживаются моками Next в памяти (`globalThis`), а не C#:

- трекинг изучения (`/api/tracking/*`);
- аналитика курса и урока (`/api/analytics/*`);
- хаб группы и лидерборд, расписание;
- обложки курсов;
- настройки системы и журнал действий.

Последствия:

- **данные пропадают** при перезапуске Next;
- **аналитика нового серверного курса пустая** (`activities: []`): преподаватель не видит в ней своих студентов;
- **режимы смешиваются**: выключение регистрации на сервере выключает её и в демо, в журнале видны действия
  из обоих режимов, прогресс материала из серверного режима виден в демо.

## 5. Демо-режим без проверки прав (так задумано)

В `src/proxy.ts` прямо указано: в демо права проверяет только интерфейс. Поэтому через API в демо:

- студент и организатор могут поставить оценку (`/api/gradebook/grade` — маршрут не вызывает `demoActorWith`,
  в отличие от users, settings, cohorts);
- студент видит работы и аналитику всех студентов, может сдать работу за другого (`userId` из тела);
- преподаватель оценивает работы и видит аналитику чужого курса;
- блокировка пользователя ничего не меняет.

На сервере все эти действия правильно отвечают 403 или 404. Если демо будет открыто наружу, это стоит закрыть.

## 6. Что работает

- **Права на сервере:** все запрещённые действия под каждой ролью дают 403 или 404, чужие курсы скрыты.
- **Регистрация:** роль и группа из тела игнорируются, создаётся студент без группы; дубль e-mail — 409;
  при выключенной регистрации — 403 и «Регистрация закрыта» в интерфейсе.
- **Курс у организатора:** создание, правка карточки, модули и материалы, публикация, архивация, привязка к группе;
  студент видит курс только после публикации.
- **Конструктор у преподавателя:** модули, материалы, порядок, навыки и предпосылки, вопросы тестов, адаптив.
- **Проверка работ:** оценка и комментарий, студент видит оценку и уведомление; повторная сдача после проверки — 409.
- **Объявления:** создаются преподавателем, студент получает уведомление; отключаются админом.
- **Группы и пользователи:** создание, переименование, состав, удаление пустой группы (непустая — 409);
  организатор не может назначить или изменить админа; себя заблокировать или сменить себе роль нельзя.
- **Блокировка на сервере:** старая сессия получает 401, вход — 403 «Учётная запись заблокирована».
- **Сквозная цепочка на сервере** «создать курс → наполнить → сдать задание → оценить → студент видит оценку»
  проходит; ломается только на тесте в новом курсе (п. 1.2).
